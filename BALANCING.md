# Admin balancing

Open Dashboard → Admin controls → Character balancing & battle lab while signed in as an admin.

Edit base character stats, numeric character skill values, enemy base stats, and numeric native enemy skill fields. Combat mechanics, skill identities, attack ranges, artifact bonuses, reward amounts and upgrade increments remain in code. Dual Gun and Dual Knife share skill definitions. Current defaults remain in effect until the first publication. Older saved configurations and history entries are loaded with default enemy values when they predate enemy balancing.

Build Team 1 and Team 2 with one to six fighters on either side. Each slot can contain any character template or enemy, including duplicates and bosses. Press **Start battle** to simulate and replay the fight in the PvP arena. Use Play/Pause, Replay and the timeline slider to inspect actions and HP/MP. Upgrade levels and Skill 2 unlocks apply to character templates; enemies retain their native abilities. No artifacts are equipped. Tests use unpublished draft values and never create characters, encounters, rewards or progression. The random seed makes comparisons repeatable, though different action sequences can consume rolls differently. The arena follows PvP movement and range rules, with no player mana regeneration for monsters. Native clerics heal fishpeople allies, while character support skills can affect mixed allies. Summons fill free living-team slots, up to six living fighters and 24 total fighters per side. Battles stop after 180 seconds or the engine's event limit. The older `/test` PvE endpoint remains available for compatibility; the dashboard uses `/arena-test`.

Use **Publish changes & patch notes** to apply values to character stats, the wiki, and new PvE/PvP simulations. A private admin note is optional. The server compares the previous published configuration with the new one and saves public before-and-after notes for changed stats and skills, including shared skill owners. Notes and the balance update are committed in one transaction. Unchanged configurations cannot be published. Players open the scroll icon beside Support in My Room to read patch notes, newest first, with older notes available through pagination. The authenticated `/api/patch-notes` endpoint exposes only patch versions, timestamps and generated changes; it does not expose admin notes, account IDs or configuration snapshots. Earlier revisions created before this feature remain available in admin history without being added to the public feed.

Already recorded battle results are preserved. A request uses its own balance snapshot so unpublished test values cannot affect other requests. The database stores the configuration and revision history, with optimistic version checking and a transaction lock to prevent concurrent overwrites. Load an earlier revision as a draft to test and republish it as a rollback, which also generates reverse patch notes. The latest ten revisions are listed in the dashboard; older revisions remain stored.

API routes are under `/api/admin/balance`. Authentication, a fresh database admin-role check, allowed-origin checks for writes, numeric bounds and admin rate limiting are enforced on the backend. The PostgreSQL migration must be deployed before starting this version of the API. Database snapshot scripts include configurations and revisions.
